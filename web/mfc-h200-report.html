Coding-Adv-HW · MFC v5.7.1 · NVIDIA H200 · 2026-11-18

MFC 在 H200 上的 GPU kernel 優化

對 MFC（Multi-component Flow Code，Fortran + OpenACC 的可壓縮多相流求解器）做原始碼層級優化。8 個 commit，主要測資快 1.75 倍，而且輸出與原版逐位元相同。

程式碼：github.com/moneychen168/Coding-Adv-HW-MFC（分支 hw-opt；與原版的差異）

1.75×主要測資，輸出逐位元相同
1.29×次要測資，輸出逐位元相同
2.72×再疊加上游 case-optimization
3.63×WENO3 kernel 本身

度量是 MFC 自己印出的 grindtime：每格點、每條方程式、每次 RHS 計算花的奈秒數，越小越好。倍數皆為 baseline grindtime 除以該配置的 grindtime。

時間花在哪裡

優化前，GPU 在整個時間步迴圈內全程忙碌，host 端開銷可以忽略。WENO3 重建佔一半，但它的瓶頸不是記憶體頻寬（DRAM 利用率只有 6%），而是指令數：每格點每變數約 1,400 道指令。

做了哪些修改

代號修改為什麼有效單項增益輸出
B1WENO3 kernel 的 private 工作陣列改成純量；變數索引移到最外層陣列尺寸是執行期變數時，OpenACC 會替每個 GPU 執行緒配置 device 記憶體暫存。光是固定尺寸就有 −11.5%−35.1%逐位元
B2重建只掃橫向內部格點Riemann solver 不讀橫向 ghost 層的重建值，那 7–8% 是白算的−1.1%逐位元
B3WENO3 非線性權重每側只做一次倒數mapped WENO3 每格每變數 16 次雙精度除法減為 4 次−3.6%非逐位元
B4WENO5/7 工作陣列改用編譯期固定尺寸和 B1 同一個病因，一行條件修改−32.2%（WENO5）逐位元
C1HLLC 直接就地寫 flux省掉每個方向一次整場複製−3.6%逐位元
C2RK 更新改為每格一個執行緒同一格的各方程式連續存取−0.7%逐位元
C3提高 nvfortran 跨檔 inline 上限（僅 GPU 目標）預設值讓 inliner 在巨大的 HLLC 函式中途停手；device call 13 → 7−2.5%逐位元
C4混合係數計算加 stiffened-gas 捷徑省掉只有狀態相依 EOS 才需要的每相除法−0.9%逐位元

單項增益是各條線在較小網格（B：503×252×252；C：316×158×158）上的 A/B 量測，不能直接相加；合併後的數字以上方結果表為準。逐位元版包含 C1–C4、B1、B2、B4；完整版再加 B3。

試過但沒採用

  • 全域 -gpu=maxregcount:128：沒有增益（+0.08%）；只對單一檔案設上限則無法連結。
  • E1（HLLC 與 cons→prim 也改固定尺寸）：單線量測 −5.6%、逐位元相同、45 個測試通過，但合併開始時還沒驗證完，沒有放進最終版，也不在公開 repo 裡。
  • B5（WENO5 除法 28 → 4 次）：WENO5 版測資 −12.2%，非逐位元、沒跑 regression，只留成 patch。

正確性

  • baseline 本身三次執行的輸出逐位元相同，所以每個修改都能直接用逐位元比對判斷。比對工具對刻意不同的輸出（第 0 步對第 60 步）會報出差異。
  • 逐位元版、baseline + case-opt 在兩個測資的最終步輸出都與 baseline 逐位元相同。
  • 完整版在主要測資不是逐位元相同（來自 B3）。以場最大值正規化的最大差是 6.2e-11（y/z 動量）；逐點相對差最大 3.4e-6，出現在動量過零點附近；能量 1.9e-10，密度與體積分率不超過 5.3e-8。
  • 每個優化配置自己三次之間逐位元可重現。

怎麼用 AI agent 完成

一個主 agent（Claude Fable 5.2）只做決策和派工，四條平行的線各自實作：

線模型工作
AOpus 5.5build、選測資、baseline、profile；最後的合併與統一量測
BFable 5.2WENO 與 RHS 的 kernel 優化
COpus 5.5HLLC、RK、編譯旗標、case-optimization
DOpus 5.5報告、投影片、旁白影片的產生流程
  • 每條線有自己的單 GPU 佔位 job，agent 只用 srun --jobid 進去編譯和執行，不在 login node 運算，也不自己送 job。
  • 依原始碼檔案分工，避免合併衝突；合併時 8 個 commit 沒有任何衝突。
  • 每個修改獨立一個 commit，同節點 A/B 三次取中位數，再做輸出比對和 regression；沒效的也記下來。
  • 非逐位元的 B3 保持獨立，另外量成一個配置，不混進標題數字。

agent 出的錯

  • B、C 兩條線第一次 git commit 都觸發 MFC 的 pre-commit hook，在 login node 跑了 1–2 分鐘 lint。之後改在計算節點處理並把警告寫進共用紀錄。
  • A 線的比對工作一度誤跑成 6 份，干擾了一次次要測資的整體執行時間（grindtime 不受影響）。
  • 旁白原定台灣男聲，服務端對新句子持續失敗，改用 zh-CN-YunyangNeural。

限制

  • 只量了單 GPU、單 MPI rank，沒有多 GPU 與擴展性數據。
  • 次要測資在 40 步內幾乎不演化，正確性判斷主要靠主要測資和 regression 套件。
  • Regression 都不含 chemistry 變體。
  • HLLC 現在佔 49.9%，每個執行緒用 196 個暫存器、occupancy 只有 12.5%，是下一個該處理的地方。
